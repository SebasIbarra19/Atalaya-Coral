# ADR-019: Agent retrieval, guarded SQL tool and evaluation dataset

- Status: Proposed
- Date: 2026-11-06
- Extends: ADR-007

## Context

ADR-007 defined the domain agent (read-only MCP tools, RAG with pgvector, structured outputs) but left open which step embeds the reference documents and what embeds the `search_docs` query. The domain is full of exact terms and acronyms (DHW, HotSpot, alert level names) that vector search alone can miss. The fixed tools answer questions about one site, but not comparisons across sites or years. The evaluation set needs answers that can be checked exactly, and it is slow to grow by hand.

## Decision

- **Document indexing job.** A batch command (a `make` target locally, a Kubernetes Job in the cluster) turns the public reference documents (PDF and HTML) into clean text, splits it by section into chunks with source, title and section, embeds each chunk with the embedding model served by Ollama and writes `doc_chunks` with the embedding and a PostgreSQL full-text vector. It is idempotent: chunks are keyed by source and content hash. `search_docs` embeds the query with the same model.
- **Hybrid search.** `search_docs` runs a pgvector similarity search and a PostgreSQL full-text search and fuses both rankings with Reciprocal Rank Fusion (k = 60). It is compared against vector-only search and against putting whole documents in the context.
- **Guarded SQL tool.** `query_sql` is a fourth read-only MCP tool. The model writes the query, and the server never trusts it: a dedicated role `atalaya_agent_sql` has `SELECT` only on an allowlist of views (no base tables, no `doc_chunks`); every query runs in a read-only transaction with a statement timeout and a row limit; a parser accepts exactly one `SELECT` over allowed views before it runs. Answers built from it cite the query.
- **Evaluation dataset generator.** Template questions whose expected answers are computed with SQL from the database (exact checks), plus document questions generated from `doc_chunks` and reviewed by hand before they enter the set. The set is versioned and runs in CI when the model, prompt, tools or indexing change.

## Alternatives discarded

- Vector-only search: misses exact terms and acronyms.
- A separate search engine (OpenSearch or Elasticsearch): one more heavy service for very little text.
- Free SQL generated by the model without guardrails: one bad query could read or change anything the role can reach.
- Only the three fixed tools: safe but rigid for comparisons.
- A hand-written evaluation set only: small and slow to grow; numeric answers are better checked exactly than judged by another model.

## Consequences

`doc_chunks` gains section, content hash and full-text columns. The views for `query_sql` and the `atalaya_agent_sql` role are created by migrations in F7. New test cases TC-26 to TC-28 and TC-30. The protocol between the dashboard and the agent is still open.
